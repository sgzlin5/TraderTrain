# TraderTrain — 计划与验收（v1 定稿）

本地 K 线回放 / 模拟交易 / 复盘工具。图表内核 klinecharts 10.1.0，自建 UI 与回放底座。
单机离线，纯自用。

| 时区口径 | 源时间直读（默认当 UTC 显示）；日线/周线聚合按 `config.sourceTz` 切，默认 `UTC` |

## 1. 数据事实（实测，2026-10）

源文件 `D:\Crypto\code\Axiom\data\XAUUSD_1.csv`：220.1 MB，**4,016,034 根**，2015-01-02 07:01 → 2026-06-27 05:58，3,570 个交易日，无重复无乱序。

| 缺陷 | 实测 | 对策 |

| `volume` 全为 0 | 100% | 隐藏 VOL 面板；指标里 `volume` 相关给 0 并提示 |

| 2023 年偏薄 | 308,752 根（正常约 353k），4 月仅 19,191 根 | 缺口密集区间只做定性复盘，不做精确统计 |

## 2. 技术基线（全部已实测）

| 项 | 选型 | 实测依据 |
|---|---|---|
| 图表 | `klinecharts@10.1.0`（锁版本） | 回放推送 300 根 6 ms；`createOverlay({points:[]})` 支持 step 取点画线；`overrideIndicator`/`getOverlays`/`subscribeAction` 可用 |
| 记录格式 | 28 B/根，小端：`int64 ts + int32×4 定点价(×1000) + float32 vol` | 定点价格零损失（2336.245 精确还原）；比 float32 省去 1.2e-4 误差 |
| 转换 | `tools/csv2bin.py`（离线，一次性） | 3 年 881,190 根 → 23.6 MB / 43.8 s；全量 ≈ 108 MB / ≈ 3 min |
| 存储 | IndexedDB：`chunks` 按年分片 + `kv` 元数据 | 写入 12 片 107.2 MB 共 1.5 s；本机配额 10,240 MB |
| 运行时读 | 按年块载入内存（9.5 MB / 20 ms）→ 内存切片 | 4000 根切片 **0.87 ms/次**（拖动/回放取窗） |
| 指标计算 | PineTS 全量预计算 → 按 timestamp 查表 | 4000 根 113 ms |
| 壳 | pywebview + 固定端口本地 http（ESM 需 http 源） | 端口必须固定，否则 Origin 变 → IndexedDB 丢数据 |

## 3. 容量策略（单次导入上限 1 GB ≠ 总容量）

两个不同的闸门，不要混：

| 闸门 | 数值 | 触发行为 |
|---|---|---|
| **单次导入上限**（应用层硬限） | **1 GB** = `1,073,741,824 B ÷ 28 B ≈ 38.3M 根` | 导入前按 `bars × 28` 预算，超过就**拒绝该次导入**并提示需要拆分区间；已存数据不受影响 |
| **总容量** | 浏览器配额（本机实测 **10,240 MB**），应用保留 20% 安全余量 ≈ 8 GB 可用 | 占用 >80% 时**只读提示 + 引导手动清理**，不自动删任何数据 |
| 截图配额（独立） | 256 MB，可调 | 只清"已导出备份"的截图 |

换算（1 GB 单次导入能装多少）：

| 数据 | 规模 | 占 1 GB 单次额度 |
|---|---|---|
| XAUUSD 1m 全量 2015–2026 | 4.02M 根 / 108 MB | 10.5% |
| 单个币种 1m 十年（约 3.6M 根） | ≈ 100 MB | 10% |
| 理论上限 | 38.3M 根 ≈ 1m × 108 年当量 | 100% |

策略：
1. 导入前预检**本次导入体积**（`bars × 28`，含元数据与缺口表），>1 GB 直接拒绝并给出建议拆分点；
2. 不做自动 LRU 淘汰（自用场景自动删数据是事故），改为**按（品种+年份）分片手动删除** + 占用面板显示各分片体积；
3. 启动时读 `navigator.storage.estimate()`，只用于告警与只读降级，不作为单次导入闸门；
4. 若配额不足导致写入失败（`QuotaExceededError`），回滚本次已写入的分片并提示，不留半截数据。

**与计划的差异（3 处）**：
1. 打包不用 pywebview —— 目的是「双击即开 + 零依赖」，Chrome `--app=` 已满足，且省掉 Python/WebView2 运行时；代价是本机需 Chrome。
2. Pine 结果不落盘缓存（脚本 hash + 数据包 + 参数）—— 一次全量重算仅 51 ms，窗口级缓存收益不足以抵消失效逻辑的复杂度。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| Pine 兼容度不可控（状态机/循环/多周期语义有偏差） | P0 | 支持特性白名单 + 编译报错到行列；跑不通就明说，不承诺"兼容 Pine" |
| 源数据缺陷（volume=0、2023 偏薄） | P0 | UI 明确标注数据质量；统计口径排除缺口密集区 |
| 单次导入超 1 GB 或配额写满导致半截数据 | P1 | 导入前按 `bars×28` 预检并强制拆分；`QuotaExceededError` 时回滚本次分片；占用 >80% 只读提示 |
| pywebview 端口变动导致 IndexedDB 丢失 | P1 | 端口写死；启动校验 origin，不一致时提示 |
| klinecharts 10.x API 演进 | P1 | 锁 10.1.0；升级前跑回归清单 |
| 回放推进与图表重绘竞争（长会话卡顿） | P2 | 游标只推 1 根/帧；切片走内存；必要时 requestAnimationFrame 节流 |
